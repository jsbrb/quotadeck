# hito-12-qwen-plan-quota — Qwen Coding Plan usage percentages via official CLI token path

## Objective
Show the Qwen Coding Plan consumed percentage (5h / weekly / monthly windows with totals and reset countdowns) in the popup, sourced from the official bailian CLI token mechanism — no cookies, no console session, reusing the stored AK/SK.

## Problem / Why
z.ai exposes quota percentages through `GET /api/monitor/usage/quota/limit`; Qwen has no percentage on any key surface (hito-8 established the binary probe). Live investigation (2026-10-25) of the **vendor's own CLI** (`bailian-cli` 2.5.1 on npm, `modelstudioai/cli` on GitHub) revealed a credential-based path: AK/SK-signed `GenerateCLIAccessToken` → Bearer-token POST to `/cli/api.json` gateway → `queryCodingPlanInstanceInfoV2` returning per-window used/total/reset. This supersedes hito-9's console-session premise (its exploration is retained on this branch as a historical reference, commit 37f71fc).

## Decisions (user-ratified 2026-10-25)
- **International site first**: hosts `bailian.ap-southeast-1.aliyuncs.com` (token) + `bailian-singapore-cs.alibabacloud.com` (gateway), commodityCode `sfm_codingplan_public_intl`. CN deferred as a purely additive follow-up (needs real CN-account evidence before requesting its hosts).
- Isolation via dedicated worktree (`quotadeck-worktrees/hito-12-qwen-plan-quota`, branch from develop @ 3851e83) — another agent is active in the main checkout on hito-11.
- The cli-token is derived material, never typed by the user; lifecycle (per-tick regenerate vs cached TTL) decided by spike evidence.
- Probe retirement (hito-8 binary 429-probe) becomes a closing decision once the quota source is live — the sk-sp- ToS tension disappears.

## Live spike evidence (2026-10-25, parent-run via official CLI)
- The maintainer's intl subscription is a **Token Plan (personal, Standard tier)** — NOT the "Coding Plan" API. `codingPlan.queryCodingPlanInstanceInfoV2` answers 200 with `codingPlanInstanceInfos: []` for all commodity codes tried (`_intl`, `_cn`, invented variants).
- Working quota surface (live, two calls): `POST https://bailian-singapore-cs.alibabacloud.com/cli/api.json?action=IntlBroadScopeAspnGateway&product=sfm_bailian&api=zeldaHttp.apikeyMgr.%2Ftokenplan%2Fpersonal%2Fapi%2Fv2%2Fusage` — `Authorization: Bearer <cliAccessToken>`, body `params={"Api":"zeldaHttp.apikeyMgr./tokenplan/personal/api/v2/usage","V":"1.0","Data":{"cornerstoneParam":{protocol,console,productCode,switchUserType,consoleSite,switchAgent}}}&region=ap-southeast-1`.
- Response (complete): `{ "per1MonthPercentage": <0..1 used fraction>, "per1MonthResetTime": <epoch ms> }`. Live cross-check vs console page: API 0.1171 used ≈ page "Remaining 88.4%" ✓; value moved between two calls (live freshness); reset carried verbatim (page expiry 2026-11-03 17:00, raw 1793721600000).
- NO used/total tokens on this surface (page's "Plan quota 45,000" comes from another subscription API; not needed — percentage+reset is the product).
- Token lifecycle client-side: `~/.bailian/config.json` stores `access_token` (36 chars) with **no expiry field**; renewal paths = browser re-login or AK/SK regeneration (unproven, see T1b).
- Browser login flow used (no cookies in our code): `bl auth login --console --console-site international` → loopback device-flow stores token; account identity echoes `userId` in envelope (strip from fixtures/docs).
